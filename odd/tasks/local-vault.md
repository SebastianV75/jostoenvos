## Specs
S1. Local organization: user proposed "Bóveda local con proyectos y ambientes." and approved the sequence "okay vamos asi, local, luego enlaces y luego evaluamos de hacer la sincronizada". Acceptance: separate project/environment documents in a local vault; no remote backend, sharing links, or team synchronization in this delivery.
S2. Files: "Importación/exportación de .env." and "Comparación de cambios antes de sobrescribir archivos." Acceptance: import and export local .env contents, preview differences before replacing an existing file, and leave a file unchanged on cancellation or a stale preview.
S3. Encryption and recovery: "Cifrado mediante librerías probadas"; the user answered "Dale con eso" to a master password and an encrypted backup restorable on another computer using that password, with no account/server password reset and OS unlock deferred. Acceptance: password-based create/unlock/lock; wrong password and tampering rejected; persisted vault and backup do not contain plaintext secrets; restoration does not require the original computer. Losing the password is unrecoverable.
S4. Platforms: "usamos los 3" refers to macOS, Windows, and Linux. Acceptance: desktop architecture supports all three; report native platform checks unavailable on this Linux host, never claim cross-platform packaging without proof.
S5. Visual direction: "para estetica y todo usa la misma estetica de justenvs.app y para todo lo visual usa las skills de ui skills y emil kowalski". Clarification: "Sobre la estética solo sácala de la landing". Acceptance: use the inspected landing's typography, restrained grid/surfaces, and green accent as the reference for desktop UI; read installed UI Skills router and Emil core skill before visual work.
S6. Verification data: "Para pruebas, usar secretos ficticios." Acceptance: fixtures and demos contain only obvious fake values; no real credentials or personal data in tests, docs, or memory.
S7. Source control: "como este es un proyecto personal y de prueba si quiero usar jj, usa su integracion para usarlo con git en el mismo repo". Acceptance: jj is the primary mutation tool in the existing colocated repo; avoid parallel Git/jj writes; parent alone commits completed work units, no remote or publishing.
